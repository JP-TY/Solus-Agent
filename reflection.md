# Reflection

Building Solus taught me more about debugging distributed pieces than about solar itself. I wanted a concierge for Philippine homes considering rooftop solar: something that could book a survey, explain net-metering, remember the customer, and do the math honestly. The trickiest design choice was the loyalty discount function. The rubric required that exact name and shape, but I also needed solar sizing, so I made one sandboxed code run do both jobs, loyalty points on one side and system size with payback on the other. Splitting it into two tools just confused the model about which calculator to call, so keeping it together was the pragmatic move. I hit something similar with survey booking: the agent kept failing until I realized the gateway only passes along what is actually written in the API spec, so the booking fields had to live there, not in the gateway settings.

Honestly the middle of the project was rough. The deployed agent spun in circles calling the calculator, and the errors said nothing useful. I had to go layer by layer through the logs. First the SDK had renamed a helper between versions, so none of the gateway tools were loading. Then the gateway role was missing permission to reach the backend, so calls died silently. And even after that, the booking schema was effectively empty, so the model's arguments were dropped on the floor. None of these were hard fixes alone, but finding them meant testing each hop directly instead of guessing, which is a habit I will keep.

If this went beyond a class demo, I would change a lot around cost and safety. The sandbox blocked every native knowledge-base option, so the docs run on a free Pinecone index behind the same retrieval API, fine for now but not something I would ship. The open auth and wide permissions were also shortcuts to keep moving. A real rollout would need proper login, tighter per-tool credentials, alarms on tool failures, and tearing down the runtime and related resources after demos so nothing idles and burns money. In the Philippines every peso of system cost matters to the homeowner, and the same should be true for how we run the backend.
