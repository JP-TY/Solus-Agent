# Reflection

Building Solus taught me more about debugging distributed pieces than about solar itself. I started with a simple goal, a helpful concierge for Philippine homes thinking about rooftop solar, something that could book a survey, explain net-metering, remember the customer, and do the math honestly. The trickiest design choice was the loyalty discount function. The rubric required that exact name and shape, but I also needed real solar sizing in the same place, so I ended up making one sandboxed code run do both jobs, loyalty points on one side and system size and payback on the other. It felt a bit forced at first, but splitting it into two tools just confused the model about which calculator to call, and renaming things would have broken the checks, so keeping it together was the pragmatic move. I ran into something similar with the survey booking. For a while the agent kept failing to book anything, and it turned out the gateway only passes along what is actually written in the API spec, so I had to define the booking fields there instead of trying to patch them in the gateway settings.

Honestly the middle of the project was rough. The deployed agent just spun in circles calling the calculator over and over, and the errors were not helpful. I had to go layer by layer through CloudWatch to figure out what was actually happening. First the SDK had renamed a helper between versions so none of the gateway tools were loading at all. Then once that was fixed, the gateway role was missing permission to actually reach the backend, so calls died silently. And even after that, the booking schema was effectively empty, so the model was sending arguments that got dropped on the floor. None of these were hard fixes on their own, but finding them meant stopping the guessing and testing each hop directly until it responded cleanly, which is a habit I will keep.

If this ever went beyond a class demo, I would change a lot around cost and safety. The sandbox blocked every AWS-native knowledge base option, so I ran the docs on a free Pinecone index behind the same retrieval API, which worked fine for now but is not something I would ship as-is. The open auth and wide permissions were also shortcuts to keep moving fast. A real rollout here would need proper login, tighter per-tool credentials, alarms on tool failures, and a habit of tearing down the runtime and related resources after demos so nothing idles and burns money. That part stuck with me because in the Philippines every peso of system cost matters to the homeowner, and the same should be true for how we run the backend.
